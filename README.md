# HeatScope

HeatScope 是一个面向落地页、官网和营销页面的增长诊断工作台，强调用可复核的证据而不是主观感觉来分析点击分布、页面承接和后续优化方向。

## 项目简介

很多页面优化讨论都会停留在“这个区块应该更显眼”或“这个按钮看起来不够突出”这样的经验判断上。HeatScope 的目标是把页面截图、热力图、结构化点击数据和业务目标放到同一个工作面里，让分析、设计、产品和增长团队围绕同一份证据协作。

## HeatScope 关注什么

- 页面点击主要集中在哪些元素和区域
- 高关注内容和核心 CTA 之间是否存在承接断层
- 页面版本变化后，点击分布为什么发生变化
- 哪些结论只是观察，哪些建议已经具备验证条件
- 如何把诊断结果整理成可执行的 UI 优化与复盘任务

## 核心能力

### 1. 证据导入

支持围绕单个页面汇集诊断材料，例如：

- 页面 URL
- 页面截图
- 热力图截图
- CSV / XLSX 行为数据
- 页面目标与设备信息

### 2. 页面诊断

围绕结构化点击数据和页面上下文输出诊断结论，包括：

- 元素点击分布观察
- 关键 CTA 承接分析
- 高兴趣区域识别
- 异常数据与映射风险提示
- 需要补充的验证指标

### 3. 优化建议输出

每条建议都应该尽量包含统一结构：

- 证据
- 判断
- 具体动作
- 验证方式
- 风险或护栏

### 4. UI Blueprint

除了给出“哪里有问题”，HeatScope 也希望继续回答“接下来该怎么改”，例如：

- 首屏目标与主次 CTA 设计
- 模块顺序调整
- 内容承接与转化路径优化
- 桌面端 / 移动端布局策略
- 事件埋点与复盘口径建议

### 5. 改版复盘

HeatScope 不把“点击变多”直接等同于“效果变好”。改版后仍需要结合：

- 页面版本
- 时间窗口
- 流量结构
- 曝光数据
- 下游结果事件

来判断变化是否具有业务意义。

## 典型工作流

1. 导入页面证据：URL、截图、热力图、行为数据
2. 识别页面中的高关注区域与关键点击分布
3. 输出诊断结论与优化建议
4. 沉淀 UI Blueprint 和事件验证要求
5. 在改版上线后回收新数据，进行前后复盘

## 设计原则

- 点击份额不等于点击率
- 热力图截图用于定位和校验，不直接作为精确计算来源
- 所有建议都应尽量附带证据与验证方式
- 缺少曝光、结果事件或实验条件时，不夸大因果结论
- 页面优化应服务于明确的业务目标，而不是只追求视觉改动

## 适用场景

HeatScope 适合用于：

- 官网落地页诊断
- 活动页 / 广告页点击分析
- 注册、试用、咨询等转化路径排查
- 页面改版前的证据整理
- 页面改版后的复盘与验证
