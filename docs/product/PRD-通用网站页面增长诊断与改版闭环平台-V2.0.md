## 1. 产品定义

### 1.1 一句话定义

HeatScope 是一个面向产品、运营、增长和设计团队的页面优化工作台：用户提交**网页 URL、同版本热力图截图和 Web 点击数据**，系统完成页面基线采集、行为数据映射、可审计诊断、优化建议、新版 UI 蓝图、实验定义与改版复盘，形成可持续积累的增长闭环。

### 1.2 适用边界

产品服务于任意拥有页面访问权限、且允许读取的 Web 页面，不限定公司、行业、技术栈或分析工具。适用页面包括：官网产品页、注册页、落地页、内容页、促销活动页、订阅页、SaaS 功能页和电商活动页。

现有的三个七牛页面仅是内置示例数据，不是产品功能边界，也不应在通用规则中被硬编码为判断依据。

### 1.3 用户完成一次分析后的交付物

1. 页面基线包：URL、采集时间、页面截图、页面版本指纹、可识别模块与元素清单。
2. 数据质量报告：文件解析、字段映射、页面/设备/日期/版本一致性、未映射元素与风险提示。
3. 热力行为诊断：点击观察、热点/冷点、CTA 承接、信息层级、决策摩擦、激活链路和待验证假设。
4. 优化清单：每项均包含证据、问题层级、页面改法、负责人、优先级、实验和护栏指标。
5. 新版 UI 蓝图：信息架构、首屏、关键组件、CTA、桌面/移动端顺序、视觉基线和交互状态。
6. 实施包：事件合同、组件规格、版本号、验收清单和 Markdown/PDF/CSV/JSON 导出。
7. 闭环复盘：改版前后版本、时间段、流量构成、实验结果和知识沉淀。

## 2. 问题与机会

### 2.1 当前问题

1. 热力图是图片，点击数据是表格，原始页面在另一个网站，人工对齐成本高且容易误判。
2. 页面优化高度依赖个人经验，建议难复用，无法解释“为什么改、怎么验收”。
3. 点击次数常被误写为点击率、转化率或留存提升，造成错误决策预期。
4. 页面改版经常只产出文案建议或低保真线框，设计、研发还要重新理解一次问题。
5. 改版后没有版本、埋点和实验合同，无法形成组织级优化资产。

### 2.2 产品机会

用 URL 建立真实页面语境，用结构化点击数据作为计算依据，用热力截图补充空间证据。再将诊断结果转换为可实施的 UI 蓝图和实验计划，让“行为观察 -> 设计决策 -> 发布验证”可复用、可审计。

## 3. 目标、非目标与成功标准

### 3.1 业务目标

1. 把一次页面分析从跨工具人工整理，收敛为一个可复查项目。
2. 让每条正式优化建议都具备数据证据、假设、实施动作和验证方式。
3. 让未知网站也能获得贴合其真实结构与视觉语言的 UI 蓝图，而非固定模板。
4. 建立页面版本与实验结果资产，提升后续优化的复用效率。

### 3.2 非目标

1. 不替代神策、Clarity、GA 等埋点平台的采集和归因能力。
2. 不绕过登录、验证码、付费墙、反爬策略或访问控制读取页面。
3. 不自动修改、发布或购买任何第三方网站内容。
4. 不依据截图像素反推精确点击数。
5. 不在缺少结果事件时宣称转化、收入或留存已提升。
6. 不把生成的 UI 预览视为已完成的前端代码或视觉验收。

### 3.3 产品成功指标

| 类别 | 指标 | 目标 |
|---|---|---|
| 效率 | 具备完整输入的单页分析完成时长 | 小于 15 分钟，不含用户准备数据 |
| 完整性 | 正式建议带证据和验证方案的比例 | 100% |
| 质量 | 元素/模块映射经人工确认后的准确率 | 大于 95% |
| 安全 | 无数据支撑却输出确定性转化或留存结论 | 0 |
| 可用性 | 导出的实施包被产品/运营采纳进入评审的比例 | 大于 60% |
| 闭环 | 已发布改版具备 page_version 和结果回填的比例 | 大于 80% |

## 4. 用户与核心场景

| 角色 | 核心任务 | 关键权限 |
|---|---|---|
| 增长分析师 | 导入、校验、发布诊断 | 创建项目、配置规则、发布报告 |
| 产品经理 | 确认问题、制定改版、回填结果 | 审阅、创建方案、管理版本 |
| 运营同学 | 调整内容、活动和 CTA | 审阅、评论、创建运营任务 |
| 设计师 | 使用 UI 蓝图完成视觉设计 | 查看基线、导出组件/规格 |
| 数据/研发 | 校验埋点和实现 | 查看事件合同、回填验收 |
| 增长负责人 | 评审优先级与结果 | 跨项目查看、审批、导出 |

### 场景 A：新网站页面诊断

增长分析师输入 URL，上传该页面同一设备、同一时间范围的点击 CSV 和热力图。系统采集页面基线，提示不一致项，完成映射后给出诊断与 UI 蓝图。

### 场景 B：活动中期调优

运营导入最近 7 天数据，发现用户频繁点击次要入口或无法定位同名 CTA。系统先给出数据修复项，再给出内容分流、优惠承接和唯一 CTA 的页面方案。

### 场景 C：产品页激活优化

产品经理看到用户在模型、价格、文档或 API Key 等模块之间往返。系统将行为放入“发现 -> 体验 -> 注册 -> 激活”的漏斗，输出上下文保留、首次价值实现和埋点合同。

### 场景 D：改版复盘

页面上线新版本后，用户新建对比批次并导入结果数据。系统对比版本、流量、设备和时间窗口，在满足数据条件时展示转化结果；条件不满足时只输出观察，不作因果归因。

## 5. 产品原则

1. **先确认页面和数据是否同一版本，再开始分析。**
2. **结构化数据用于计算，截图用于空间定位与人工校验。**
3. **本地规则负责底线与可审计性，模型负责受约束的解释和创意候选。**
4. **UI 方案从原页面的结构与视觉基线出发，不套固定行业模板。**
5. **结论层级随数据完备度升级，低层级不能越级承诺结果。**
6. **每条建议都必须能被实施、埋点和验证。**
7. **默认最小化采集，不上传访问凭据、用户输入内容或敏感页面数据。**

## 6. 数据层级与输入合同

### 6.1 数据层级

| 层级 | 最低输入 | 可以输出 | 禁止输出 |
|---|---|---|---|
| L0 页面基线 | URL 或原始长截图 | 页面模块、可见 CTA、视觉基线 | 行为或效果结论 |
| L1 点击观察 | L0 + 元素点击数据 + 热力图 | 点击量、份额、集中度、热点、优化假设 | CTR、转化、留存、因果结论 |
| L2 页面效率 | L1 + 页面 PV/UV 或模块曝光 | 页面点击效率、元素 CTR、触达问题 | 未接入结果事件的转化结论 |
| L3 转化诊断 | L2 + 注册/下单等结果事件 | 漏斗转化、分段流失、优化结果对比 | 未经实验验证的因果结论 |
| L4 留存验证 | L3 + 匿名用户标识和留存事件 | 分群留存、行为相关性 | 将相关性表述为因果性 |

### 6.2 创建项目必填项

| 字段 | 是否必填 | 规则 |
|---|---|---|
| 页面 URL | 是 | 必须为 http/https，记录最终跳转 URL |
| 页面目标 | 是 | 可选注册、咨询、试用、购买、内容消费、自定义关键动作 |
| 设备与视口 | 是 | 例如 desktop 1440、mobile 390；必须与热力图一致 |
| 数据时间范围 | 是 | 开始、结束、时区 |
| 点击数据文件 | 是 | CSV/XLSX，至少含元素标识与点击次数 |
| 热力图截图 | 是 | 需包含页面、设备、时间范围或由用户确认一致 |
| 原始页面截图 | 条件必填 | URL 无法采集、内网页面或动态页面时必须上传 |
| 页面版本 | 强烈建议 | 发布日期、版本号、Git commit、截图指纹至少一项 |
| 目标 CTA | 强烈建议 | 名称、选择器/链接、业务定义 |

### 6.3 点击数据最小字段

`date, page_url, device_type, element_name, element_selector_or_id, element_link, click_count`

推荐补充：`click_uv, page_pv, page_uv, module_id, event_name, traffic_source, page_version, experiment_id`。

系统必须：

- 使用 UTF-8 BOM 兼容解析；
- 结构化读取 CSV/XLSX，不按逗号手拆；
- 显式排除“总和/Total”汇总行，避免重复累计；
- 将同名元素与同一元素区分，默认不聚合；
- 对输入框、搜索框、聊天框等可能含个人输入的元素脱敏或排除；
- 报告中显示数据层级、字段缺失、解析失败行和质量分。

## 7. 端到端产品流程

```text
创建项目
  -> 页面基线采集/上传回退
  -> CSV/XLSX 与热力图导入
  -> 一致性校验与元素映射
  -> 本地规则诊断
  -> 可选模型增强
  -> 洞察与优先级确认
  -> UI 蓝图与实施包
  -> 任务/实验创建
  -> 新版本结果导入
  -> 复盘与知识库沉淀
```

每一步均可回退修改；未通过质量门槛的项目不能发布为“正式诊断”，但可保存为草稿。

## 8. 功能需求

### 8.1 页面基线采集

#### FR-01 URL 采集

用户提交 URL 后，系统在服务端只读访问公开页面，记录：最终 URL、标题、主语言、截屏、视口、采集时间、HTTP 状态、页面结构摘要、可见链接/按钮、主要图片区块和页面指纹。

采集策略：

1. 使用指定的设备视口渲染页面。
2. 生成桌面/移动端长截图与 DOM 结构摘要。
3. 识别候选模块：导航、首屏、CTA、表单、价格、内容卡片、FAQ、页脚等。
4. 识别品牌基线：主色、辅助色、字体栈、圆角、间距密度、按钮风格。
5. 保存 `page_snapshot_id` 和 `page_fingerprint`，不保存 Cookie、账号会话、表单内容或凭据。

失败回退：遇到登录、网络限制、前端渲染失败、robots 限制或内网地址时，明确显示原因，并要求用户上传原始页面截图、HTML 导出或经批准的内部访问代理结果。不得绕过访问控制。

#### FR-02 页面版本管理

同一 URL 可存在多个页面版本。版本由 URL、截图哈希、DOM 哈希、用户填写版本号和采集时间共同识别；变更超过阈值时提示重新映射热力图和元素。

### 8.2 数据导入与映射

#### FR-03 智能字段映射

系统识别常见分析平台字段，并允许用户将源字段映射到统一字段。每个映射配置可保存为“数据源模板”，供同一公司下次复用。

#### FR-04 元素与模块映射

映射优先级：

1. `page_version + selector/id` 精确匹配；
2. `link + 可见文本 + DOM 位置` 匹配；
3. 用户在页面截图上点选确认；
4. 未映射项保留在待处理列表，不参与空间结论。

系统要展示映射置信度和冲突。例如同名“立即购买”出现在 43 个模块时，必须提示缺少 `module_id/product_id/cta_type`，不能将其归因为某一个卡片。

#### FR-05 质量门槛

| 检查项 | 阻断级别 | 处理 |
|---|---|---|
| URL、设备或日期不一致 | P0 | 禁止发布正式诊断 |
| 页面版本明显不同 | P0 | 要求新截图或确认继续 |
| 点击数据无法解析 | P0 | 阻断导入 |
| 关键 CTA 无法映射 | P1 | 降低结论置信度并提示人工确认 |
| 未映射元素占比过高 | P1 | 不输出空间布局结论 |
| 缺少 PV/UV 或结果事件 | P2 | 限制到对应数据层级 |

### 8.3 分析引擎

#### FR-06 本地规则引擎

本地规则默认启用、可离线复现。至少覆盖：

- 点击集中度、异常、重复 CTA、零点击与数据缺失；
- 高兴趣内容与弱转化承接；
- 主 CTA 可见性/文案/位置风险；
- 导航或辅助入口分流；
- 价格、套餐、模型、规格等决策摩擦；
- 注册、试用、API Key、首次成功动作等激活缺口；
- 活动页的人群分流、优惠信息与归因缺口；
- 页面版本、设备、日期和映射不一致风险。

规则输出统一结构：`证据 -> 判断 -> 备选解释 -> 建议动作 -> 验证方式 -> 主指标 -> 护栏 -> 置信度 -> 数据层级`。

#### FR-07 可选模型增强

用户可选本地规则、混合分析或模型分析。模型服务支持多个供应商配置，但 API Key 只用于当前请求，不写入项目、报告或浏览器持久化。

发送给模型的内容最小化为：页面结构摘要、已确认模块、脱敏点击聚合、热力图摘要或用户明确勾选的截图、规则证据和页面目标。模型不得覆盖数据边界；其输出必须经过 JSON Schema 校验和证据引用检查。

模型可做：运营角度解释、文案候选、模块排序候选、UI 内容建议。模型不可做：虚构数据、承诺提升、把点击当作结果事件、绕过 URL 访问限制。

### 8.4 洞察与优化方案

#### FR-08 洞察工作台

每条洞察展示：优先级、漏斗阶段、问题标题、可定位页面模块、结构化数据证据、热力图证据、可信度、运营原则、建议动作、需要补充的数据和实验定义。

洞察支持人工编辑、驳回、合并、评论、分配负责人和引用到报告。系统保留规则/模型版本和人工修改历史。

#### FR-09 优化计划

产品和运营可将洞察转换为优化计划。计划字段：`owner, due_date, page_version_target, change_scope, hypothesis, primary_metric, guardrails, experiment_type, status`。

### 8.5 新版 UI 蓝图生成

#### FR-10 生成原则

UI 蓝图不是通用卡片拼接，而是由以下输入共同生成：

1. 原页面信息架构和视觉 Token；
2. 已确认的高/低兴趣模块与 CTA；
3. 页面目标、用户意图和数据层级；
4. 运营规则与已选优化计划；
5. 桌面/移动端约束。

#### FR-11 蓝图输出

每个项目至少输出：

- 新旧页面结构对照；
- 首屏标题、价值说明、主/辅助 CTA 与承接规则；
- 模块顺序、每个模块的目的、内容字段和交互状态；
- 可复用组件清单：导航、按钮、筛选、卡片、价格、表单、步骤、FAQ 等；
- 色彩、字体、间距、边框和组件风格的“继承/调整”说明；
- 桌面和移动端布局、折叠与吸底 CTA 规则；
- 页面事件合同和属性；
- 一份可预览的高保真 HTML 方案；
- Markdown/PDF 导出；后续支持 Figma 变量、组件和前端代码导出。

#### FR-12 UI 生成流水线

```text
页面基线 -> 模块树/设计 Token -> 行为问题映射
-> 选择页面策略 -> 生成蓝图 Schema -> 规则校验
-> 高保真预览 -> 人工编辑/批准 -> 实施包
```

`页面策略` 包含但不限于：注册激活、产品选型、企业询价、活动促销、内容转化、表单完成、电商商品选择。未知页面先分类，再调用对应策略；分类置信度低时，要求用户选定目标，不假设行业。

### 8.6 实验、结果与知识库

#### FR-13 事件合同

每个方案自动生成统一事件名和页面专属属性。例如：

| 事件 | 必填属性 | 用途 |
|---|---|---|
| `page_view` | page_id, page_version, device_type, experiment_id | 版本与流量分母 |
| `module_exposure` | module_id, position, page_version | 确认模块触达 |
| `cta_click` | module_id, cta_type, target_url | 比较 CTA 承接 |
| `goal_start` | goal_type, entry_position | 注册/购买等开始动作 |
| `goal_complete` | goal_type, page_version | 真实业务完成 |
| `activation_complete` | activation_type, context_id | 首次价值实现 |

业务方可扩展属性，但 `module_id`、`page_version` 和 `cta_type` 为页面优化的推荐最小标准。

#### FR-14 复盘

系统要求选择改版前后版本、时间窗口和流量条件。若无实验分流或足够结果事件，报告只能写“观察到变化”，不能写“改版导致提升”。系统自动提示渠道、节假日、设备和版本混杂风险。

## 11. 安全、隐私与权限

1. 仅采集用户有权提交的 URL；系统不使用账号登录、Cookie 或密码访问第三方页面。
2. 禁止上传 API Key、密码、手机号、订单明细、聊天输入等敏感信息；导入前执行字段提示与脱敏检查。
3. 页面截图、DOM 摘要、原始文件、模型请求和报告按项目权限隔离。
4. 模型 API Key 不持久化；模型调用记录模型名、时间、输入摘要哈希和输出版本，便于审计。
5. 支持项目级数据保留期、删除、导出和访问日志。
6. 对内网页面，使用用户上传的截图/HTML 或企业批准的代理采集，不直接从公有部署服务访问内网。

## 13. 验收标准

1. 用户可创建任意域名的项目，不依赖预置页面 ID。
2. 页面采集失败时，用户可通过截图/HTML 完成同样的分析流程，且原因可见。
3. 任何 L1 项目报告均展示“点击观察”，不出现未经数据支持的转化或留存承诺。
4. 同名 CTA 未带模块标识时，系统提示不可归因，不生成伪精确排序。
5. UI 蓝图至少包含页面对照、模块/组件、移动端规则、CTA、事件合同和预览。
6. 更换 URL 后，预览保留该网站的页面结构和视觉基线，不显示其他公司名称、固定页面文案或专属模板。
7. 运行模型增强时，系统显示模型、输入范围、时间和可追溯的输出版本。
8. 发布复盘时，若缺少结果事件或实验条件，系统限制结论措辞。

## 14. 风险与决策

| 风险 | 影响 | 产品决策 |
|---|---|---|
| URL 无法采集或动态渲染失败 | 无真实视觉基线 | 截图/HTML 上传回退，不绕过权限 |
| 只有点击次数 | 不能证明业务结果 | 强制 L1 边界与数据缺口提示 |
| 截图和数据版本不同 | 映射失真 | 以版本质量门槛阻断发布 |
| 模型幻觉或过度营销文案 | 不可信建议 | 规则证据、Schema、人工审批三重约束 |
| 不同网站 DOM 差异大 | 模块识别不稳定 | 规则 + 视觉 + 人工确认混合映射 |
| 设计方案过度同质化 | 无法落地 | 先提取页面 Token/结构，再选策略生成 |
| 第三方数据合规 | 隐私与安全风险 | 最小采集、脱敏、权限、保留期与审计 |
