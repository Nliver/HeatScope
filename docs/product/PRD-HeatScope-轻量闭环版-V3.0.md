# HeatScope 轻量闭环版 PRD

> 版本：V3.0 | 日期：2026-07-30 | 状态：实施基线

## 1. 产品定义

HeatScope 是一个轻量级页面增长诊断工具。用户上传页面 URL、热力图截图和网页行为数据表，系统以本地规则和可选多模型分析形成可审阅洞察、UI 改版参考与上线后复盘。

它服务于任意网站，不绑定七牛、神策或 Clarity。神策、Clarity 只是首批数据来源；CSV/XLSX 是当前统一输入格式。

## 2. 本期目标与边界

### 目标

1. 在一次浏览器会话内完成“证据导入 -> 分析 -> UI 蓝图 -> 前后数据复盘”。
2. 让产品、运营、设计、前端使用同一份有证据、有动作、有验证方式的实施包。
3. 支持多个用户自定义模型在同一冻结证据包上并行分析和人工比较。
4. 以运营方法论约束建议：优先识别注册前承接、CTA 引导、兴趣到行动断层、套餐决策摩擦和低门槛试用路径。

### 非目标

1. 不替代神策、Clarity、GA4 的采集、归因或报表能力。
2. 不自动登录、爬取受权限保护页面，不保存 Cookie、密码或用户输入。
3. 不自动修改、生成可直接发布的原网页源代码。本能力列入下一期“受控源码改造”。
4. 不在缺少分母、结果事件或实验条件时声称 CTR、转化、留存、收入或因果提升。
5. 不将热力图像素颜色当作精确点击数。

## 3. 核心流程

```text
Step 1 导入证据
  URL + 页面目标 + 设备 + 热力图截图 + CSV/XLSX 行为表
        ↓
Step 2 分析与模型对比
  本地规则（必经） + 同一证据包的多模型并行调用（可选）
        ↓
Step 3 输出实施包
  洞察、优化清单、UI Blueprint、事件合同、Markdown 导出
        ↓
Step 4 上线复盘
  导入改版后同口径数据，显示观察变化与缺失验证条件
```

## 4. 用户与任务

| 用户 | 主要任务 | 成功结果 |
|---|---|---|
| 增长/运营 | 发现承接、内容、CTA 问题 | 获得可分配的优化动作与验证指标 |
| 产品经理 | 判断改版优先级 | 获得有证据的假设、事件合同和复盘要求 |
| 设计/前端 | 将建议实现为真实页面 | 获得模块顺序、CTA、组件内容、响应式规则 |
| 增长负责人 | 比较不同分析意见 | 获得同证据的模型输出与人工决策依据 |

## 5. Step 1：输入与质量门

### 输入

| 输入 | 必填 | 规则 |
|---|---:|---|
| 页面 URL | 是 | `http/https`，仅建立页面语境，不自动抓取受保护页面 |
| 页面目标 | 是 | 注册/试用、购买/询价、内容消费、活动领取或自定义 |
| 设备 | 是 | 桌面端或移动端，需与热力图、行为表保持一致 |
| 热力图截图 | 是 | PNG/JPG/WEBP，作为空间复核，不用于数值计算 |
| 行为数据表 | 是 | CSV/XLS/XLSX，至少含元素名称和点击次数 |
| 核心 CTA | 强烈建议 | 由用户选择或输入；同名 CTA 应带模块/选择器 |
| 背景说明 | 选填 | 说明投放、页面版本、时间范围、业务目标 |

### 解析与质量规则

- 自动排除 `总和`、`合计`、`Total` 等汇总行。
- 支持 UTF-8 BOM CSV、首个 XLS/XLSX 工作表；识别常见元素、点击、PV/UV、模块、选择器、链接字段。
- 行为表是数值唯一来源，截图仅供人审和页面位置判断。
- 同名元素缺少 `module_id` 或 `selector` 时，显示“不可归因”，不合并到某一页面位置。
- 无 PV/UV 时为 L1；有页面 PV/UV 时为 L2；是否可以得出转化/留存结论另取决于结果事件，不由点击表替代。

## 6. Step 2：分析机制

### 本地规则（默认、必经）

输出字段固定为：`证据 -> 判断 -> 具体动作 -> 验证方式 -> 护栏`。

| 规则 | 触发示例 | 结果 |
|---|---|---|
| 映射风险 | 同名 CTA 无模块/选择器 | P0 埋点治理，禁止位置归因 |
| 主 CTA 未定义 | 未标记核心业务动作 | P0 补齐主路径定义 |
| CTA 承接弱 | 主 CTA 在已记录点击中份额较低 | P1 收敛首屏 CTA、在高兴趣区增加就近承接 |
| 兴趣到行动断层 | 内容/模型/价格区高点击但非 CTA | P1 补适用场景、成本解释与下一步动作 |
| CTA 竞争 | 多个行动型入口并列 | P2 区分主/次 CTA 与 entry_position |
| 数据不足 | 无 PV/UV、曝光或目标事件 | 限制结论层级并列出补数清单 |

运营方法论的应用原则：

- 注册或接入意图优先使用“免费获取 API Key / 立即免费接入”等低门槛主 CTA；模型、文档和体验为辅助入口。
- 套餐与企业购买先解决“适合谁、多少钱、能立刻做什么”的决策问题；给套餐增加业务体量/场景锚点。
- 资源包和低门槛选项先保证曝光与可理解性，再讨论购买 CTA。
- 高兴趣区后提供就近行动，不让用户返回首屏重新寻找下一步。

### 多模型比较

1. 用户在当前会话填写名称、Base URL、模型 ID、协议（Responses 或 Chat Completions）和 API Key。
2. 只在“开始分析”时将密钥通过 HTTPS 发送给 Next.js Route Handler；密钥不写入浏览器持久化、日志、导出文件或数据库。
3. 每个已启用模型收到相同 `Evidence + LocalAnalysis + JSON Schema + Prompt`，以及浏览器压缩后的热力图视觉输入；保留每个模型的成功/失败、耗时和完整结果。
4. 不做多数投票。用户可阅读分歧，手动选择一个模型的 UI 蓝图候选；本地规则始终保留。
5. Route Handler 仅允许 HTTPS 公网地址，并拒绝 localhost、私网地址和内部域名，降低 SSRF 风险。

## 7. Step 3：交付物

### 洞察与优化建议

每条建议必须具备：优先级、数据证据、可能解释、具体动作、验证指标、护栏。缺数据时只写“可能”“待验证”，不得写“必然提升”。

### UI Blueprint

蓝图用于设计、产品和前端协作，至少包含：

1. 页面策略和首屏目标。
2. 主/次 CTA 及其承接规则。
3. 模块顺序、模块目的、内容字段与交互状态。
4. 桌面端与移动端布局原则。
5. 事件合同：`page_view`、`module_exposure`、`cta_click`、`goal_start`、`goal_complete`。
6. 可预览的结构参考与 Markdown 实施包导出。

蓝图明确不是对用户 URL 的自动代码修改，也不是视觉验收完成证明。

## 8. Step 4：复盘

用户上传改版后同口径行为表。系统比较前后总点击和主 CTA 点击观察，并提示必须补齐的条件：

- `page_version`、时间窗口、设备、渠道/流量构成；
- 页面 PV/UV、模块曝光；
- `goal_start` / `goal_complete`；
- 实验分流或可比对照。

未满足条件时，报告措辞为“观察到变化”，禁止表述“改版带来提升”。

## 9. 轻量架构

```text
Browser (Next.js / React)
  ├─ 本地解析 CSV/XLSX
  ├─ 本地显示热力图、规则结果、UI 蓝图、导出
  └─ 当前内存保存项目输入与模型 Key，并压缩热力图供视觉模型分析
              ↓ 仅在发起模型分析时
Next.js Route Handler /api/analyze
  ├─ 校验模型 URL（HTTPS / 公网）
  ├─ 并行转发 OpenAI Compatible Responses / Chat Completions
  └─ 返回本次模型结果，不保存 Key 或文件
```

技术实现：一个 Next.js 16 + React 19 应用；TypeScript；Tailwind CSS v4；Radix UI（后续交互扩展）；`xlsx` 浏览器解析。部署为一个支持 Node.js Route Handler 的 Vercel 项目或任意 Node 运行环境。

本期不需要 Go、PostgreSQL、Redis、Docker、对象存储、后台队列、Vault 或独立 Worker。未来如果需要团队项目长期保存、权限、历史案例库、大文件、任务协作，再增量引入服务端存储与鉴权。

## 10. 验收标准

1. 不配置任何后端地址也能导入 CSV/XLSX、热力图，完成本地规则分析、蓝图展示、复盘和 Markdown 导出。
2. 可添加 1-4 个模型；模型失败时显示原因且不会丢失本地分析结果。
3. 所有模型使用同一证据指纹、提示词约束和输出 Schema。
4. API Key 刷新后消失，不出现在下载的 Markdown、页面存储或服务端日志。
5. L1 输出不包含未定义的 CTR、转化、留存或因果结论。
6. UI Blueprint 一定包含首屏、模块、CTA、桌面/移动端说明和事件合同。
7. 复盘页面在缺少实验/结果数据时明确提示限制，不把点击量变化作为业务提升。

## 11. 下一期：受控源码改造

输入增加原页面源码仓库或授权的 HTML/CSS/组件上下文；系统基于已审批 Blueprint 生成变更候选、组件差异和测试清单。必须包含 Git 分支、代码审阅、视觉回归和人工发布审批，不能由当前轻量工具自动上线。
