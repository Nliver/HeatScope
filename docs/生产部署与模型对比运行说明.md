# HeatScope 生产部署与模型对比运行说明

## 运行边界

`apps/web` 是静态 Next.js 工作台，只负责用户交互；它不包含 API Key、数据库密码、任务逻辑或网页采集能力。`apps/api` 和 `apps/worker` 必须部署在受控网络中，并使用同一个 PostgreSQL、Redis、对象存储和 Vault/KMS。

模型对比是异步任务：API 创建冻结输入的 `ModelComparison` 与多条 `ModelExecution`，写入 Outbox；Worker 的 dispatcher 投递 Asynq，再由分析 Worker 执行。模型失败不会覆盖其他模型结果，比较状态会是 `partial` 或 `failed`。

## 必填配置

| 变量 | API | Worker | 说明 |
| --- | --- | --- | --- |
| `DATABASE_URL` | 是 | 是 | PostgreSQL 连接串 |
| `REDIS_ADDR` | 否 | 是 | Asynq Redis 地址 |
| `VAULT_ADDR` | 是 | 是 | Vault 地址或企业 Secret 服务适配地址 |
| `VAULT_TOKEN` | 是 | 是 | 仅由工作负载身份注入，不能进入前端 |
| `VAULT_KV_MOUNT` | 是 | 是 | KV v2 mount，本地默认 `secret` |
| `AUTH_MODE` | 是 | 否 | 生产必须接 OIDC 网关，不能为 `development` |
| `CORS_ORIGIN` | 是 | 否 | 静态工作台的精确来源，多个值用逗号分隔 |
| `NEXT_PUBLIC_API_BASE_URL` | Web 构建时 | 否 | 公网 API 前缀，例如 `https://api.example.com/api/v1` |

生产环境不要设置 `AUTO_MIGRATE=true`。应由受控的迁移 Job 在应用发布前执行 Ent migration，并在发布窗口内验证 RLS、组织隔离和备份恢复。

## 本地拓扑

使用 Docker 时：

```bash
docker compose -f deploy/docker-compose.yml up --build
```

本地 compose 中的 Vault dev token、数据库密码和 MinIO 凭据只可用于本机；不得复用到任何共享环境。默认使用 Vault dev 的 `secret` KV mount；共享环境应使用企业 Vault/KMS 适配器和工作负载身份。

工作台开发环境：

```bash
cd apps/web
cp .env.example .env.local
npm run dev
```

将 `.env.local` 中的 `NEXT_PUBLIC_API_BASE_URL` 指向 API。生产前端必须以该变量重新构建，不能在浏览器侧保存模型 Key。

## 模型档案与对比

1. 管理员创建模型档案：Provider、Base URL、协议、模型、输出上限和超时。
2. 页面经 TLS 将密钥提交至 `POST /model-profiles/:id/secret`；API 仅把它写入 Vault，数据库只保存 `secret_ref`。
3. 使用连接测试确认 Provider 支持结构化输出；至少两个可用档案才能创建对比。
4. 导入点击观察，确认元素映射后发起模型对比。
5. 比较页核查 `frozen_input_hash`、Prompt/映射/规则/Schema 版本，逐项审阅候选的证据、数据层级合规、耗时、Token 与失败原因。
6. 人工选择、合并或驳回候选；系统不会按多数投票自动发布。

## 上线前质量门

- 运行 `go generate ./ent`，并在 CI 执行 Ent migration、API、Worker、Vault 和 PostgreSQL 集成测试。
- 使用真实公网模型域名测试 DNS 私网/回环拒绝、重定向、超时、配额和 Schema 无效输出。
- 验证组织 A 无法查询组织 B 的项目、资产、比较、任务和模型档案。
- 验证同一 `Idempotency-Key` 的重试返回稳定结果，不同请求复用同一 Key 被拒绝。
- 前端执行 `npm run build`，并在真实 API 上跑“导入 -> 两模型对比 -> 人工选择 -> 导出”E2E。
